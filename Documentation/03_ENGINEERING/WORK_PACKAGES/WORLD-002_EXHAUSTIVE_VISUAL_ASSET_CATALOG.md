# WORLD-002 — Exhaustive Visual Asset Catalogue

**Scope:** Complete visual-asset inventory required for the WORLD-002 validation preview described by the approved work package. This is exhaustive for the WORLD-002 preview scope, not a catalogue of every asset the final game will ever need.

**Status:** Owner-approved initial visual scope: four terrestrial biomes (plains, forest, desert, mountains) plus water presentation. This catalogue remains limited to the WORLD-002 validation preview; later production art still requires its own approval. Existing files must be re-audited on the active branch and exact Unity GUIDs recorded before production use.

## 1. Important distinction: generated data is not an art asset

The following WORLD-002 outputs are generated by the Unity world-generation systems and must not be added to Blender's model batch as if they were FBX assets:

- Height, temperature, water, slope, distance-to-water and moisture fields.
- Vegetation suitability/density field.
- Biome classification field.
- Settlement suitability fields and candidate markers.
- Spherical/planisphere debug visualisations, legends and exported map images.

These are data products / runtime or editor visualisations. Blender's `generate_all.py` is for approved Blender-authored visual assets (models), not for generating the planetary maps or Unity materials/prefabs.

## 5. Definition of exhaustive and change control

This catalogue is exhaustive for the minimum WORLD-002 visual validation scope: plains, forest, desert/dry ground, water presentation, and a representative hybrid vegetation preview with at least two tree silhouettes.

It is not exhaustive for the final game. It does not include settlement buildings, roads, fences, bridges, crops, biome-specific rocks, snow/ice assets, seasonal variants, Pokémon habitat props, or the full production vegetation catalogue. Those belong to later approved work packages and must not be silently added to WORLD-002.

Any new required visual asset discovered during implementation must be added to this catalogue, assigned a stable key/source/destination/status, and approved before its production generation.


## 6. Initial URP material-generation implementation

The initial Unity Editor material-generation slice is implemented in:
- `Assets/Project/Editor/World/Spherical/Biomes/SphericalBiomeMaterialGenerator.cs`
- `Assets/Project/Runtime/World/Spherical/Presentation/SphericalBiomeMaterialMapping.cs`

Run **Tools → World → Generate or Refresh Biome Materials (URP)**. The tool creates or refreshes:
- `MAT_Ground_Plains.mat`
- `MAT_Ground_Forest.mat`
- `MAT_Ground_Desert.mat`
- `MAT_Ground_Mountains.mat`
- `MAT_Water_Surface.mat`
- `CFG_BiomeMaterialMapping.asset`

Materials use `Universal Render Pipeline/Lit`. This first pass assigns authored base-colour tints, zero metallic and biome-specific smoothness values. It deliberately does not invent or generate albedo/normal/roughness textures. Existing texture assignments are preserved when the tool refreshes a material. The mapping asset exposes a material lookup by `SphericalBiome` and a water material reference.

**Important boundary:** generating these assets does not yet apply them to the spherical planet mesh. The current presenter still owns one terrain material for all six faces. A later presentation increment must implement biome-aware surface assignment and seam-safe transitions using the shared `SphericalGeographicFieldSet`; it must not duplicate biome classification or alter geographic fields.


## 3.8 First stylized ground-texture increment

**Owner-approved direction:** modern Pokémon-inspired stylized textures (clear painted-looking variation, readable colour blocks, low-to-moderate contrast; not photorealistic). This approval applies to the initial WORLD-002 ground-texture prototype.

The first texture increment uses deterministic Editor-generated, tileable albedo-detail maps rather than introducing external texture packages or Blender FBX dependencies:

- `Assets/Project/Runtime/World/Spherical/Presentation/SphericalBiomeTextureGenerator.cs` creates deterministic 512×512 RGBA detail maps for Plains, Forest, Desert and Mountains. The generator uses periodic multi-frequency value noise and biome-specific low-contrast marks; it is runtime-safe and testable, but the Editor currently owns asset creation.
- `Assets/Project/Editor/World/Spherical/Biomes/SphericalBiomeMaterialGenerator.cs` writes the generated PNG assets to `Assets/Project/Content/Textures/Environment/Biomes/Generated/` and assigns them to the four URP/Lit ground materials as `_BaseMap`. Re-running the material command refreshes these generator-owned files.
- `SphericalBiomeMaterialMapping.ConfigureBlendMaterial` forwards the four albedo maps into the shared blend material.
- `SphericalBiomeBlend.shader` samples the four maps using world-space triplanar projection, then blends their tinted results with the existing geographic biome weights. This avoids face-local UV seams and does not modify classification or field data.
- Initial texture world size is 18 m per repeat. This is a tuning default, not a final art lock; adjust only after inspecting ground-level and aerial views on the target PC.
- Textures are albedo-detail multipliers only. They do not yet include authored normal, height, ambient-occlusion or roughness maps. Water remains a separate smooth colour surface in this increment.

### Texture acceptance checks

- Same biome + seed produces byte-identical pixels.
- PNG imports use Repeat wrapping, bilinear filtering, mipmaps and anisotropic filtering.
- Texture projection has no visible discontinuity at Cube-Sphere face boundaries or poles during a slow orbit.
- Ground texture scale remains readable at player height and does not become high-frequency noise at medium/far distances.
- Biome blending remains driven by the existing shared field weights; texture generation must not classify biomes or change world seed/field output.
- Re-running the generator preserves material references and refreshes only the explicitly generator-owned generated texture paths.
